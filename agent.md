# Documentation guidelines

`README.md` is only for human-friendly explanations. Keep it approachable,
conversational, and focused on what Fetchary does, why it is useful, and how
someone can get started.

- Use plain English and short explanations that sound natural to a human reader.
- Explain features through practical user scenarios and small, runnable examples.
- Preserve the README's simple structure and tone when adding or changing content.
- Keep exhaustive option lists, API definitions, implementation details, and edge
  cases out of the README.
- Put the complete command reference, flags, output formats, and CLI behavior in
  `docs/CLI.md`.
- Put library usage, API options, and TypeScript details in `docs/LIBRARY.md`.
- Record release changes in `docs/changelog.md`.
- For new features, update the reference documentation. Add a short README
  explanation or example only when it helps a human understand or use Fetchary.
